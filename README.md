#Рекомендательная система постов в социальной сети: персонализация ленты на основе профиля пользователя и его активности
| | |
|---|---|
| **Описание проекта** | Построение рекомендательной системы постов для социальной сети студентов karpov.courses. <br> **Заказчик:** Платформа karpov.courses. <br> **Цель:** Усовершенствовать ленту: показывать не случайные посты, а точечные рекомендации, учитывая профиль пользователя, его прошлую активность (просмотры, лайки) и содержимое постов. <br> **Данные:** Три таблицы в PostgreSQL: `user_data` (профили), `post_text_df` (тексты и темы постов), `feed_data` (история просмотров и лайков). |
| **Задачи** | Провести EDA и загрузку данных из БД.<br>Создать признаки (пользовательские, постовые, временные).<br>Обучить модель, оптимизирующую прокси-метрику для максимизации HitRate@5.<br>Соблюсти ограничения: время инференса ≤ 0.5 сек, память ≤ 4 ГБ.<br>Разработать FastAPI-сервис с эндпоинтом `/post/recommendations/`, возвращающим топ-5 постов для любого user_id в любой момент времени.<br>Сохранить модель и признаки, загрузить в чекер LMS. |
| **Ход проекта** | 1. **Загрузка данных:** подключение к PostgreSQL, выгрузка таблиц с учётом большого объёма `feed_data` (чанками).<br>2. **EDA и создание признаков:** анализ распределений, генерация признаков (возраст, город, пол, OS, источник; текст поста, тема; время, лаги активности, скользящие статистики лайков и просмотров).<br>3. **Обучение модели:** выбор алгоритма (коллаборативная фильтрация, контентная или двухэтапная модель). Валидация на временном срезе (предсказание для тех же юзеров в будущем). Контроль метрики HitRate@5.<br>4. **Сохранение модели:** экспорт весов в файл.<br>5. **Разработка сервиса:** написание скрипта на FastAPI, загрузка модели и признаков (из БД с помощью `batch_load_sql`), формирование предсказаний для запрашиваемого `user_id`, возврат 5 постов в формате `PostGet`.<br>6. **Загрузка в чекер:** отправка кода сервиса и модели в LMS для финальной проверки. |
| **Выводы** | Целевая метрика HitRate@5 должна превысить **0.52**.<br>Сервис должен обрабатывать запрос в среднем быстрее **0.5 секунды** и потреблять не более **4 ГБ RAM**.<br>Успешное прохождение чекера на 2000 запросов подтверждает готовность модели к продакшену.<br>Рекомендации: при необходимости уменьшить количество фичей или использовать более лёгкие модели для ускорения инференса и соблюдения лимитов памяти. |
| **Стек** | Python (Pandas, NumPy, Matplotlib, Seaborn)<br>База данных: PostgreSQL, SQLAlchemy (batch_load_sql)<br>API: FastAPI, Pydantic (схема PostGet)<br>ML: scikit-learn, рекомендательные библиотеки (Surprise, implicit, LightFM) или PyTorch/TensorFlow для эмбеддингов<br>Метрики: HitRate@5, Precision/Recall, время инференса |

| **Описание проекта** | Разработка рекомендательной системы постов для социальной сети студентов karpov.courses.<br>**Заказчик:** образовательная платформа karpov.courses.<br>**Цель:** построить ML-сервис персональных рекомендаций, который для каждого пользователя в реальном времени возвращает наиболее релевантные посты из ленты соцсети.<br>**Данные:** таблицы `user_data` (профили пользователей), `post_text_df` (тексты и темы постов), `feed_data` (история просмотров и лайков пользователей). |
| **Задачи** | Провести исследовательский анализ данных (EDA) пользовательских профилей, постов и истории взаимодействий.<br>Построить pipeline генерации признаков для пользователей и постов.<br>Создать обучающую выборку на основе просмотров и лайков пользователей.<br>Реализовать текстовые признаки с использованием TF-IDF и статистических признаков взаимодействий.<br>Обучить и сравнить несколько ML-моделей для предсказания вероятности лайка.<br>Оценить качество моделей с помощью ROC-AUC и HitRate@5.<br>Реализовать сервис рекомендаций на FastAPI.<br>Оптимизировать скорость работы и потребление памяти под ограничения LMS.<br>Сохранить модель и реализовать загрузку признаков из PostgreSQL. |
| **Ход проекта** | 1. **Загрузка и изучение данных:** выполнено подключение к PostgreSQL, загружены таблицы `user_data`, `post_text_df` и часть `feed_data`. Проведен анализ структуры данных, типов признаков, пропусков и распределений пользовательской активности.<br><br>2. **EDA:** исследованы распределения лайков, просмотров, активности пользователей и популярности постов. Выявлен сильный дисбаланс классов — лайков существенно меньше просмотров. Анализ текстов постов показал наличие тематических кластеров и различий в вовлеченности пользователей по тематикам.<br><br>3. **Feature engineering:** созданы пользовательские признаки (CTR пользователя, количество просмотров и лайков, активность по времени), признаки постов (CTR поста, популярность, тема), временные признаки (час, день недели), а также TF-IDF признаки текстов постов. Подготовлена обучающая выборка с объединением пользовательских, текстовых и статистических признаков.<br><br>4. **Моделирование:** протестированы `Logistic Regression`, `Random Forest`, `CatBoost` и `LightGBM`. Для оценки качества использовались `train/test split` и кросс-валидация. Лучшее качество показал `CatBoost` благодаря работе с категориальными признаками и устойчивости к дисбалансу.<br><br>5. **Валидация:** проведена временная валидация с разделением по `timestamp` для имитации реальных пользовательских запросов в будущем. Основной метрикой итоговой оценки являлся `HitRate@5`.<br><br>6. **Сохранение модели:** обученная модель сохранена локально и протестирована после повторной загрузки.<br><br>7. **Разработка сервиса:** реализован FastAPI-сервис рекомендаций с endpoint `/post/recommendations/`. Сервис загружает модель и признаки при старте приложения, получает `user_id` и `timestamp`, формирует признаки и возвращает топ-N рекомендованных постов.<br><br>8. **Оптимизация:** реализована потоковая загрузка признаков из PostgreSQL через `batch/chunk processing` для соблюдения ограничений RAM (<4 ГБ). Проведена оптимизация скорости предсказаний для прохождения ограничения ~0.5 секунд на запрос. |
| **Выводы** | Построена рекомендательная система персонализированной ленты постов для социальной сети.<br>Наиболее эффективной моделью оказался `CatBoost`, показавший лучшее качество на задаче ранжирования постов.<br>Использование пользовательских статистик, TF-IDF текстовых признаков и временных факторов позволило существенно улучшить качество рекомендаций.<br>Временная валидация показала, что модель способна обобщаться на будущие взаимодействия пользователей.<br>Реализованный FastAPI-сервис успешно формирует рекомендации в режиме реального времени и соответствует ограничениям по памяти и скорости работы.<br>Дополнительная оптимизация загрузки данных через `batch processing` позволила стабильно работать с большими объемами `feed_data`.<br>Для дальнейшего улучшения качества рекомендаций можно использовать эмбеддинги текстов, нейросетевые модели и sequence-based подходы. |
